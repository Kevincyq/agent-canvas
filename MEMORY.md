In fullscreen, `.canvas-session-content` must be a flex column so the FluxInk widget consumes the remaining height and the compact voice panel stays capped near 22dvh/180px.
- Resilient Azure realtime ASR (2026-07-11): monitor recognizer session/canceled events plus `Connection` connected/disconnected events, close terminated recognizers, and rebuild them with 1s/2s/4s backoff up to three attempts while retaining transcript segments. Refresh the 600-second STS token on the active recognizer two minutes before expiry. Recovery and terminal interruption must be visible in the voice UI; errors after prior transcript content must not be console-only.

CSP must include `blob:` in `script-src` and an explicit `worker-src 'self' blob: data:`; otherwise the first utterance can succeed while subsequent recognition stalls because the SDK timer worker is blocked.
- Optional voice attachment UX (2026-07-11): handwriting structured content remains the primary AskAI query and voice recording is optional. Once transcript text exists, show that it is attached in the recorder, collapsed canvas summary, and composer; include it only in that request's `attachments`, then persist a collapsed voice-attachment card on the sent user message so users can verify what the AI received.
- Typed AI answer blocks (2026-07-14): AI answers now support explicit `blocks` in addition to the short `message` and legacy actions. The editable source contract distinguishes Markdown, table JSON, Mermaid, LaTeX, graph JSON/GraphML, and media SVG/image instead of forcing every visual into `render_svg`. Mermaid is retained as source and rendered to SVG in the browser; SVG remains a media/fallback format for free-layout visuals. Each typed block exposes an ellipsis menu with Edit/Copy/Download. Edit opens one unified document editor for the entire answer, with block-specific editing and live preview; save updates the local chat answer in place for this PoC. Legacy `render_svg` actions and fenced SVG replies are converted into media blocks for compatibility. Development-only `/typed-blocks-demo` returns all six block types for local UI verification.
- Handwriting-to-diagram fidelity boundary (2026-07-14): FluxInk's composer handoff currently provides linear recognition text rather than a canonical node-edge/layout structure. Asking the model to reinterpret that text as a Mermaid mind map can lose the original 2D topology and invite semantic expansion; Mermaid then applies its own automatic layout and cannot recover handwritten coordinates. For faithful normalization, preserve a canonical graph/layout representation first, constrain the model to exact nodes and edges, and treat Mermaid or SVG as derived renderers rather than the source of truth.
- Recognition-input versus AI-answer format boundary (2026-07-15): treat `handwriting recognition -> AskAI context` and `AskAI answer -> editable UI blocks` as separate contracts. Recognition should preserve canonical type-specific facts and metadata (for example graph JSON nodes/edges/layout/confidence) and may add an LLM-friendly Mermaid/Markdown/LaTeX derivative; the preview is only a frontend rendering of that source. AI answer blocks may independently choose the best editable format per output type. The visible composer may show a concise summary or attachment, while the request payload carries the full structured context; do not flatten rich `structuredContent` into one display string.
- Editable AI document behavior (2026-07-15): within the PoC, AI answer formatting is fixed by output content type: text=Markdown, formula=LaTeX, flowchart=Mermaid flowchart, mind map=Mermaid mindmap, table=table JSON, and structure diagram=graph JSON. All blocks render as styled cards and open in one document editor; table and graph blocks use structured controls while source-oriented blocks edit their native text. “Save as new document” preserves the original answer and appends an independent in-memory document copy with new block IDs; persistence to a backend document library remains outside the current PoC.
- Handwriting mind-map fidelity guard (2026-07-15): the current FluxInk linear descriptor uses shape and connector terms such as `quadrilateral`, `circle`, `ellipse`, `line`, and `arc` as visual metadata, not semantic labels. `/api/agent` now reinforces that rule in the model contract and deterministically corrects matching mind-map responses by extracting only recognized labels, preserving simple node shapes, and replacing invented category layers with the first recognized node plus direct branches. This guard fixes the current star-shaped contract (`ProjA -> B/C/D`); arbitrary multi-level topology still requires canonical edges or layout coordinates from the recognition provider rather than inference from flat text.
