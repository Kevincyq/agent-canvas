## Current Technical Shape

- Frontend: Next.js, React, TypeScript, tablet-portrait AskAI shell with FluxInk MCP App widget + Azure realtime ASR. `HandwritingCanvas.tsx` remains as the unused native-canvas path.
- Backend: Next.js API routes. Canonical Agent entry is `POST /api/agent/run`; old `POST /api/agent` returns 410.
- Agent layer: singleton Ask AI Agent in `src/lib/agent/` (`@openai/agents@0.13.2`) with Tool Registry, Tool Policy/approval, SqliteSession, and structured output.
- Workflow layer: P0.5 Registry in `src/lib/workflows/` (`native` Dralk, `fixture` Meeting, `external_pending` Writing Assist / Translation).
- MCP layer: server BFF in `src/lib/mcp/` hosts FluxInk widget resources and allowlisted JSON-RPC.
- Persistence: SQLite under `./data/agent-canvas.sqlite` (`SQLITE_PATH`).
- Shared protocol types live in `src/types/` (`agent.ts`, `agent-runtime.ts`, `agent-stream.ts`, `workflow-runtime.ts`, `tool-gateway.ts`).
- Cloud Tool Gateway / Connector registry: `src/lib/tools/`. Agent tools keep LLM schemas; FluxInk / Tavily / Azure ASR / PKB / ToDo / Calendar go through `getDefaultToolGateway()`.
- AskAI chat transport: browser uses HTTP SSE (`Accept: text/event-stream`) on `/api/agent/run` and `/resume`; evals without that Accept header still receive one-shot JSON. Charts/blocks render only after a complete object event.
- The workspace also contains `openai-agents-js/`, an embedded OpenAI Agents JS monorepo/reference checkout with its own `AGENTS.md`.
- Canonical product/runtime snapshot for humans is root `README.md` (rewritten 2026-09-14), including the business-architecture mermaid diagrams.

## Durable Decisions

- Streaming duplicate-answer bug (2026-09-17): `CanvasAgentApp` read `streamingAssistantIdRef.current` *inside* the `setMessages` updater. React runs functional updaters during a later render, but the `finally` block's `resetStreamingAssistant()` runs synchronously first, so `streamId` was already `null` when the filter executed — the temporary streaming message survived next to the final one and the same answer rendered twice. Rule: never read a ref inside a state updater when the ref is mutated later in the same synchronous block; capture it into a local const before calling `setMessages`. Verified server-side output is not duplicated (one `answer.message`, one `done`).
- Token-level streaming over structured output (2026-09-17): `runAskAiTurn` / `resumeAskAiRun` now call `runner.run(..., { stream: true })` and `drainStreamedRun` consumes `raw_model_stream_event` / `output_text_delta`. Those deltas are fragments of one structured-output JSON document, so `parsePartialJson` (`src/lib/agent/partial-json.ts`) tolerantly closes the in-flight buffer each chunk and re-parses it; unparseable boundaries (bare key, trailing comma) return `null` and are skipped until the next chunk. Streamed: `message` (`answer.delta`) and markdown block `source` (`block.delta`, keyed by array index via `STREAMING_BLOCK_ID_PREFIX` because the block's own id is still streaming). Deliberately NOT streamed: table / mermaid / latex / graph / charts / svg — truncated sources render as broken output, so they stay gated on `block.completed`. `answer.message` and `block.completed` remain authoritative and replace anything accumulated from deltas. Measured: first delta ~3.3s vs `done` ~13.8s, streamed text byte-identical to the final payload.
- Most answer prose lives in `blocks`, not `message` (2026-09-17): the model routinely puts a one-line preamble in `message` (8–19 chars observed) and the real content in markdown blocks. Any streaming or progress feature that only handles `message` will look broken to the user. Verify streaming work against block content, not just `message`.
- FluxInk transport-error classification (2026-09-17): a canvas-open failure surfaced as bare `TypeError: fetch failed` with the real reason only in `error.cause.code` (`UND_ERR_CONNECT_TIMEOUT`, 10s undici connect timeout — unrelated to `MCP_TIMEOUT_MS`). `isMcpSessionError` matched only `error.message`, so the shared-client reconnect retry never fired and the host showed no actionable text. `src/lib/mcp/client.ts` now walks the `cause` chain (`describeMcpError`) and classifies undici/socket codes as transport errors, which both enables the one reconnect retry and produces a Chinese "无法连接 FluxInk MCP" message naming `MCP_SERVER_URL`. Root cause of that incident was the local proxy tunnel (`mcp.fluxink.ai` resolves to fake-IP `198.18.0.190` via the Clash-style proxy on `127.0.0.1:7897`); the endpoint itself was healthy. Note Node's undici ignores macOS system proxy settings, so diagnose with plain `node fetch`, not only `curl`.
- Tool Gateway typing follow-up (2026-09-17): `ToolGateway.invoke` is generic (`invoke<TData>`) so `ServiceAdapters` contracts keep their `ToolReceipt<Shape>` payload types while connectors stay untyped and swappable. Also fixed a real bug from the gateway migration: the `fluxink.recognize` connector read `result.ok`/`result.error`, but `callAllowedMcpTool` throws on transport failure and returns a payload using `success`/`error`, so every successful recognition produced `ok: undefined` and `/api/hwr/recognize` always answered 502.
